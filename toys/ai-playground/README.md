# AI の遊び場（ブラウザ内 LLM がキャンバスで遊ぶ）

言語モデル **Qwen3 4B**（`onnx-community/Qwen3-4B-ONNX`）が、右の **640×480 のキャンバス 1 枚**に、JavaScript で**思うままに**描いたり動かしたりする。
何をするかは指示しない。左にモデルの思考（Qwen3 の思考モード）・説明・書いたコード・実行の結果が流れ、右でキャンバスが変わっていくのを眺める。
推論も実行も、すべてこのブラウザの中（[Transformers.js](https://github.com/huggingface/transformers.js) の WebGPU）。

**PC 向け**: WebGPU と fp16（`shader-f16`）に対応したブラウザ（Chrome など）が必要。Qwen3 4B の ONNX は `q4f16` しか無い（約 2.7 GB。初回だけダウンロードし、ブラウザに保存）。

## 使い方

- 「開始」でモデルを読み込み、ステップを繰り返す（回数の上限は無い）
- 「一時停止」: いまのステップが終わったところで止まる（もう一度押すと取り消し）。止まるのを待っている間は「いますぐ止める」で生成を途中で止められる
- 「止める」→「続きから始める」で、同じキャンバス・同じ履歴のまま続けられる
- 「ページを初期化」でキャンバスを初期化する（プログラムを止め、memo も消す。モデルにも、次のステップでそう伝える）
- キャンバスはクリック・キー入力を受け取る（モデルがゲームなどを作ったら、遊べる）
- 設定: 思考モード（既定 ON）・1ステップの最大トークン数（既定 2048）・ステップの間の待ち時間（既定 1 秒）。ブラウザに保存
- 「ログをコピー」で、思考・説明・コード・結果をテキストでコピーできる

## 遊び方のしくみ（キャンバス 1 枚・プログラムの上書き）

- キャンバスは 1 枚だけ。**DOM は使えない**（`document`・`window` などに触ると、「キャンバスの関数と `say()` を使って」というエラーになる）
- **1 回のコード = 1 つのプログラム**。実行するたびに、前のプログラム（draw の繰り返し・タイマー・クリックやキーの受け取り）を止め、キャンバスを黒で消してから動かす。
  前のものを育てるときは、モデルが前のコードを直して全体を書き直す
- 次のプログラムに残るのは **`memo`（オブジェクト）だけ**
- 毎回まっさらから始まるので、canvas やアニメーションが積み重なって重くなることが無い

モデルに用意した関数（名前は p5.js に寄せた。モデルが慣れているので）:

| 種類 | 関数 |
| --- | --- |
| 流れ | `setup(() => {…})`（最初に 1 回）・`draw((t, dt) => {…})`（毎フレーム）。`function setup() {…}`・`function draw() {…}` と書いても動く |
| 描く | `background`・`fill`・`noFill`・`stroke`・`strokeWeight`・`noStroke`・`circle(x, y, 半径)`・`ellipse`・`rect`・`line`・`poly`・`text`・`push`・`pop`・`translate`・`rotate`・`scale`・`ctx`（Canvas 2D そのもの）・`W`・`H` |
| 色 | `'red'`・`'#ff8800'`・`hsl(色相, 彩度, 明るさ)`・`rgb(r, g, b, a)`・`fill(255, 0, 0)` など |
| 計算 | `random`（範囲・配列から選ぶ）・`randInt`・`noise`（パーリンノイズ 0〜1）・`lerp`・`map`・`clamp`・`dist`・`PI`・`TAU` |
| 入力 | `mouse.x`・`mouse.y`・`mouse.down`・`keys.last`・`keys.isDown(キー)`・`onClick((x, y) => …)`・`onKey((key) => …)` |
| 文字 | `say(…)`: キャンバスの左上に文字を出す（題名・点数・説明） |
| その他 | `memo`・`setTimeout`・`setInterval`（同時に 20 個まで。プログラムの上書きで止まる）・`console.log` |

小さなモデルがつまずきやすいところは、こちらでやわらげている: 線は `stroke()` が無くても `fill` の色で引く /
描く関数に数でないものを渡すと「数を渡して」とエラーにする / `const draw = …` のように用意した関数と同じ名前を使ってもぶつからない。

## 1 ステップの流れ

1. モデルに、system（遊び方・使える関数）と、**直近 4 ステップ**のやりとり、いまの知らせを渡す（ずっと続けても文脈が伸びない）。
   - 前のステップの知らせは**短い形**（成功・エラー・console の出力だけ）。絵のようすと重さは、いまの知らせだけに入れる（入力を短くして、1 ステップを速くする）
   - それより前のステップ（最大 12）は「ステップ n: したこと」の1行ずつにまとめて添える（忘れて同じことを繰り返さないように）
2. モデルが「何をしたいか」と、```js で囲んだ JavaScript を1つ書く（思考モードなら、その前に `<think>…</think>` で考える。左に思考ログとして出す）
3. コードを右のサンドボックスで実行し、0.8 秒動かす
4. 結果を、次のステップの知らせとしてモデルに返す:
   - 成功 / **エラー（原因を考えて直すよう促す）** / setup・draw・タイマー・入力の関数の中のエラー（draw の中なら繰り返しを止める）/ 処理されなかった Promise の失敗
   - console の出力
   - **絵のようす**（モデルは画像を見られないので、文字にする）: キャンバスを 32×12 の文字に縮めた図（暗い ` ` 〜 明るい `@`）・多い色・
     0.5 秒でどれだけ変わったか（動いているか）・プログラムのようす（setup・draw・クリック・キー）・`say` の文字。真っ黒のままなら、そう伝える
   - **重さ**: 1 秒あたりのフレーム数・draw 1 回にかかった時間・処理で埋まっている時間。重いとき（draw 平均 20 ms 以上・負荷 35% 以上など）は、軽くするよう促す
   - 前とほとんど同じコード（似ている度合い 95% 以上）だったとき: そう伝え、「思いつきのたね」を添える
   - コードが無かったとき: 「```js で囲んで書いて」/ 応答が無かったとき（無限ループなど）: 初期化したこと / 失敗が 3 回以上続いたとき: 別のやり方を促す
5. 履歴には思考を入れない（Qwen3 の推奨。文脈も節約）

最初の知らせには、50 個ほどの「思いつきのたね」（時計・迷路・ライフゲーム・花火・小さなクイズ など）から 3 つを選んで添える
（毎回同じことから始めがちなので。使うかどうかはモデルの自由）。

**重すぎるときは初期化**: 実行のあとの負荷が 85% 以上、または実行していないときも負荷 75% 以上が 5 秒続いたら、ページを初期化して、次の知らせでそう伝える
（負荷 = 20ms ごとのタイマーがどれだけ遅れたか。タブが見えていないときは数えない）。右上に重さ（fps・draw の時間・負荷）を 1 秒ごとに表示する。

## サンドボックス（このページを守るしくみ）

キャンバスは `sandbox.js` の iframe の中で動く。用意した名前（`document` を使えなくするなど）は遊び方のためのもので、守りは次の iframe の仕組みが受け持つ。

- **`sandbox="allow-scripts"` だけ**（`allow-same-origin` を付けない）。中のページは「どこでもない origin」になり、
  このページ（親）の DOM・localStorage・Cookie に触れない。親の移動・ポップアップ・フォーム送信・alert もできない
- 中のページに **CSP（`default-src 'none'`）**。fetch・外部の画像・スクリプトなど、ネットワークは使えない
- 親とのやりとりは postMessage だけ。親は送り主がこの iframe かを確かめ、結果を決まった形・長さにそろえ（縮小図は決まった文字だけ）、文字として表示する
- コードは iframe の中で関数として実行する（`"use strict"`。宣言しない変数への代入はエラー）
- **無限ループの見張り**: `for (…) {`・`while (…) {`・`do {`・本体が空のループ（`while (x);`）・波かっこの無い1文のループ（`while (x) y++;`）に
  `__lp()` を差し込み、イベントループに戻らずに 2 秒以上回り続けたら、エラーにして止める（draw の中でも。モデルに返して直させる）
- 結果が 8 秒以内に返らなければ（実行の仕組みが壊れた など）、iframe を作り直す。中のページが別のページへ移動しようとしたときも作り直す

## テスト

```sh
sh toys/ai-playground/test/setup.sh     # 初回だけ（Transformers.js・ONNX Runtime Web・小さなテスト用モデル・本物の Qwen3 のトークナイザ）
python3 -m http.server 8000             # リポジトリのルートで
node toys/ai-playground/test/e2e.cjs
```

ヘッドレス Chromium で 66 項目:

- キャンバス: 描いて縮小図・多い色・say・console の出力を返す / memo だけが次に残り、キャンバスと say は消える / const・let・function は毎回別 /
  `document`・`window`・`requestAnimationFrame` は使えず、何を使えばいいかをエラーで伝える / 宣言しない変数への代入はエラー /
  draw で動き、動いていることを返す / 新しいプログラムで前の draw とタイマーが止まる / `function setup()`・`function draw()` の書き方 /
  エラー（コード・setup・draw・タイマー・Promise・再帰）/ タイマーは 20 個まで / クリックの位置（キャンバスの座標）とキー入力
- 隔離: 用意した名前を通らずに（間接 eval で）触っても、**親の DOM・localStorage・ネットワーク・親の移動には届かない**
- 無限ループ（波かっこあり・本体が空・1文・draw の中）を止め、そのあとも続けられる / 見張りを入れても答えが変わらない / 中のページの移動・document.write のあとも続けられる
- 重さ: 表示 / 重い draw の負荷と時間を測る / 重すぎる状態が続いたら初期化する（memo も消える）
- 知らせの文: 縮小図・色・動き・プログラム・say・重さ・軽くする促し・短い形・真っ黒・初期化・繰り返し・思いつきのたね・前にしたことのまとめ
- 繰り返し（決まった答えを返す偽のモデル）: エラーを返して次で直す / コードが無いときの知らせ / 絵が動いていることを返す / 絵のようすはいまの知らせだけ /
  失敗が続いたときの知らせ / 直近 4 ステップだけを渡し、それより前は1行ずつのまとめを添える / 思考を表示し、履歴には入れない / 一時停止・再開・止める / ログのコピー
- 本物の Qwen3 4B のトークナイザ: 思考モードの切り替え（`enable_thinking`）がチャットテンプレートに効く
- 小さなテスト用モデル（本物の推論の流れ）: 読み込んでステップが回る
- スマホ幅 / CDN と Hugging Face 以外へ通信しない / ページのエラーが無い

**確かめられていないこと**: 本物の Qwen3 4B での動作（この作業環境に GPU が無く、q4f16 は WebGPU と fp16 が要る）。速さ・遊び方の中身。

## 既知の制約

- **見張れない重い処理では、ページ全体が止まることがある。** 見張りを入れられない形のループ（1文が複数行にまたがる、`for (…) if (x) y;` など）や、
  ループの無い重い処理（巨大な配列を作るなど）は止められない。iframe がこのページと同じスレッドで動くブラウザ（ヘッドレス Chromium で確認）では、
  ページ全体が固まる。そのときはタブを再読み込みする（設定は残る）
- 重い draw は、初期化されるまでの数秒は重くなる。メモリの使いすぎは測っていない（memo に巨大なものを入れ続けるなど）。「ページを初期化」でいつでも戻せる
- 縮小図は 32×12 の明るさだけなので、細かい絵や色の違いはモデルに伝わらない
- モデルは長く動かすほど似たことを繰り返しやすい（直近 4 ステップしか覚えていない。前のことは1行のまとめだけ）
- 推論は `../tinyswallow-chat/` の `worker.js`・`runner.js`・`models.js` を使う
